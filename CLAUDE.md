# Ozonologist — правила проекта

**Начни с `PROGRESS.md`** — целиком. Там архитектура, что сделано и
**очередь задач (§11)**: бери сверху, у каждой задачи есть «зачем, что
сделать, где, когда готово».

## Принципы (всё, что уже построено, держится на них)

- **Считает код, модель только формулирует.** Метрики, формулы, правила,
  закономерности, план поставок — детерминированный код. Модель получает
  готовые факты и не выводит новых чисел. Исключение — чтение текста (отзывы):
  модель относит отзыв к теме **строгой схемой**, считает всё равно код.
- **Нет данных — это «нет данных», никогда не 0.** `unknown`/`unavailable`
  не участвуют в правилах и не попадают в причины. Ноль в отчёте — это
  измеренный ноль.
- **Факт отдельно от гипотезы.** Совпадение в данных — факт; процесс, который
  к нему привёл, — гипотеза и подаётся как «похоже…».
- **Рекомендация — действие с адресатом** (производство, логистика,
  маркетинг, коммерция, контент, склад), а подъём цены — всегда тест с мерой
  успеха.
- **Одна граница с Ozon** — `src/integrations/ozon/store.ts` (мок ↔ живой) и
  реестр инструментов `src/knowledge/tools.ts`. Живой режим без источника
  возвращает null, а не выдуманные данные.
- **Мок — витрина, а не заглушка.** Данные должны изображать грамотный
  кабинет с конкретными дырами. Каждая заложенная история закреплена тестом.
  Правило, срабатывающее на трети ассортимента, — шум, а не диагностика:
  калибровать пороги по распределению.

## Перед коммитом — всё зелёное

```bash
npx tsc --noEmit
npm run eval     # офлайн: без модели и без сети; каждая новая логика — с тестом
npm run build
npm run lint     # 3 старые проблемы в _ui/conversations.tsx и page.tsx — известны
```

На живой модели проверять через запущенный dev-сервер:
`curl -s -X POST localhost:3000/api/agent-chat -H 'Content-Type: application/json' -d '{"messages":[{"role":"user","content":"…"}]}'`

## Как работать

- Коммиты — на русском, подробное тело: что, зачем и что нашлось по дороге.
  Пуш в `main`. Перед пушем `git pull --rebase`: владелец иногда правит файлы
  прямо на GitHub.
- Ключи — только в `.env.local` (в `.gitignore`), никогда в чат и в код.
  Ключ Ozon — с ролью «только чтение»: агент ничего не меняет в кабинете.
- Владелец не любит длинные ответы и «роботный» тон — и в чате с ним, и в
  ответах агента. Голос агента задан в `src/agents/ozonologist.ts`
  (`OZONOLOGIST_VOICE`) позицией и примерами, а не форматом из слотов:
  слоты («Главная причина:», «Что сделать:») и делают ответ роботом.
- Цель проекта — демо к работе менеджером маркетплейсов (косметика и
  парфюмерия, ~3000 SKU, собственное производство) и инструмент, который
  потом закрывает рутину на реальном кабинете.
